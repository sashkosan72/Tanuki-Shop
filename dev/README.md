# Локальні дані Tanuki Shop

`schema.sql` — fixture для ізольованої локальної SQLite/D1. Її відтворено з SQL-запитів поточного `src/index.js`; фактичну схему production D1 ще не звірено. Цей файл не є production baseline або міграцією й не повинен застосовуватися до віддаленої бази.

Він створює дев’ять таблиць, потрібних наявним каталогові, замовленням, Telegram-прив’язці та підтримці. Унікальність `order_number`, `telegram_id`, `token_hash` і `order_telegram_links.order_id` підтримує пошук та `ON CONFLICT` у Worker. Локальні foreign keys та індекси не підтверджують, що production має такі самі обмеження чи індекси. Бізнес-правила перевіряє наявний код; fixture не додає тригерів або нового механізму резервування.

`seed.sql` додає три явно демонстраційні товари: акційний товар із залишком, товар без залишку та товар без складського обліку. Ціни подано цілими гривнями, як у поточному застосунку. Покупців, замовлень, секретів і зовнішніх зображень seed не містить.

Обидва файли можна виконувати повторно: схема використовує `IF NOT EXISTS`, seed — `ON CONFLICT(id) DO NOTHING`. Повторний seed не перезаписує змінені ціни чи залишки демотоварів. `IF NOT EXISTS` не оновлює вже створену застарілу локальну таблицю; у разі зміни fixture потрібне окреме узгодження локальної схеми.

Для запуску використовуйте локальні команди з кореневого README та локальну конфігурацію проєкту. Не передавайте ці файли командам із `--remote` і не підміняйте ними схему наявної `tanuki-shop-db`. Для production спочатку потрібні read-only звірка схеми, перевірене відновлення та окремі додавальні міграції.
