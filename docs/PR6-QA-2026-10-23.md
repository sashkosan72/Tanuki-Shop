## Current authentication change

Hosted WebCrypto rejects the original 180000 PBKDF2 iterations. The first JavaScript fallback preserved hashes but repeatedly exceeded the free Worker CPU budget (observed 503/exceededCpu). It has been removed.

The current Preview uses native PBKDF2-HMAC-SHA256 at 100000 iterations, followed by HMAC-SHA256 with a separately stored, random 256-bit CUSTOMER_PASSWORD_PEPPER secret. Hashes are explicitly versioned with the prefix pbkdf2-sha256-hmac-v1$. Missing/invalid pepper fails closed. The secret must be retained; rotation requires password resets. Never copy the Preview pepper into production; provision a distinct production secret before enabling customer auth.

Security tradeoff: 100000 iterations is below OWASP's 600000 recommendation for PBKDF2-SHA256. The separate pepper adds protection against a database-only compromise but does not make the lower work factor equivalent when both the database and secret are compromised. This remains a release-review concern, not a claim of equivalent cryptographic strength.
Reference: https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html

Legacy Preview accounts are preserved. Their next login returns an explicit reset-required response instead of attempting expensive JavaScript hashing. Telegram password recovery writes the new version and invalidates existing sessions and other reset links. Unverified legacy accounts can use their original confirmation link before recovery. Expired unverified legacy accounts need a secure recovery design; do not overwrite them without ownership proof.
