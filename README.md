# Tanuki Shop

Наявний інтернет-магазин на Cloudflare Workers: вітрина, каталог і замовлення в D1, фотографії в R2, адмінпанель та Telegram-сповіщення й підтримка.

Домен: [tanukishop.pp.ua](https://tanukishop.pp.ua). Наявність домену в документації не підтверджує поточний стан deployment.

## Локальний запуск

Потрібні Node.js 24 і npm. Для встановлення залежностей потрібен доступ до npm registry.

```bash
npm install
cp .dev.vars.example .dev.vars
npm run db:local:init
npm run db:local:seed
npm run dev
```

У `.dev.vars` задайте окремий локальний пароль адміністратора. Значення секретів у цьому файлі не комітяться. Для базової перевірки каталогу й замовлень Telegram-секрети не потрібні.

`npm run dev` використовує `wrangler.local.jsonc`: локальні D1/R2 і наявний каталог `public`. Сервер слухає `http://127.0.0.1:8787`, адмінпанель — `/admin/`. `dev/schema.sql` і `dev/seed.sql` містять лише локальну тестову схему й демонстраційні товари. Це не схема або міграція production.

## Перевірки

```bash
npm run check
npm test
npm run build:check
```

Node-тести виконують код Worker з SQLite-адаптером у пам’яті й тестовими даними. Вони не підтверджують роботу реальних Cloudflare D1/R2 або доставки Telegram. `build:check` готує dry-run збірку без публікації.

Wrangler зафіксований на версії `4.151.3`. У поточному середовищі встановлення залежностей не завершилося через недоступний мережевий доступ, тому `package-lock.json` ще не створено, а команди Wrangler не перевірено. Після успішного `npm install` потрібно перевірити dry-run і додати згенерований lockfile; після цього наступні встановлення виконуються через `npm ci`. `npm run check` та `npm test` не потребують зовнішніх залежностей і перевірені на Node.js 24.

## Поточні межі

Авторизація покупців, підтвердження email, Telegram-вхід на сайт, особистий кабінет і окремі сторінки товарів ще не реалізовані. Наявний checkout гостьовий. Telegram зараз прив’язує конкретне замовлення після покупки. KeyCRM підключений як чат-віджет; обміну замовленнями через API немає.

Аудит також виявив дефекти узгодженості замовлень і залишків та перемикання чатів підтримки. Додавання засобів розробки саме по собі їх не виправляє. Узгоджена ціль: каталог відкритий усім, checkout і кабінет доступні після входу.

Докладні команди та межі середовища — у [посібнику розробника](docs/DEVELOPMENT.uk.md), наступні зміни й критерії готовності — у [плані розвитку](docs/ROADMAP.uk.md).
