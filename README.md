# Tanuki Shop

Існуючий інтернет-магазин на Cloudflare Workers зі статичним frontend (`public/`),
backend (`src/index.js`), D1 (`DB`), R2 (`PRODUCT_IMAGES`) і Telegram-ботом.
Цей репозиторій продовжує поточний магазин, а не створює новий з нуля.

## Безпечна локальна перевірка

Потрібні Node.js 24+ і npm. У тестах використовується тільки ізольована
SQLite в пам'яті; запити до реальної D1, Telegram або R2 не надсилаються.

```bash
npm ci
npm run check
npm run deploy:check
```

`deploy:check` — це **dry-run**, він не публікує Worker. У середовищі, де
користувацька конфігурація недоступна для запису, можна задати стандартну
змінну `XDG_CONFIG_HOME` на доступну тимчасову папку.

## Етап 1: замовлення та захист API

- Запис замовлення, позицій і зменшення залишків виконується однією
  транзакцією `D1.batch()`. Якщо за цей час товар закінчився або змінилася
  ціна, API повертає `409` і не створює замовлення.
- Для `/api/admin/login` і `POST /api/orders` передбачені окремі Cloudflare
  Rate Limiting bindings (відповідно 5 і 10 запитів за 60 секунд на IP у
  кожному Cloudflare location). Це допоміжний захист, а не глобальний
  абсолютно точний лічильник.
- Відсутній або несправний rate limiter спричиняє `503` — небезпечні POST
  не проходять без захисту.
- Пароль адміністратора та Telegram-секрети залишаються у Cloudflare
  Secrets, а не в репозиторії.

**Не запускати реальний deploy без погодження.** Перед майбутніми змінами
схеми D1 потрібні перевірка міграцій на тестовій БД та резервна копія.
У цьому етапі схема існуючої D1 не змінюється.

## Етап 2: акаунти покупців (гілка `codex/stage2-customer-auth`)

**Код підготовлено локально, але на робочому сайті його ще немає.**

- Підтвердження email через одноразове посилання, чинне 24 години;
  пароль хешується PBKDF2-SHA256 із унікальною сіллю. Непідтверджений
  email не дає права увійти або оформити покупку.
- Telegram Login Widget для `TanukiShopNotifyBot` з перевіркою підпису
  HMAC-SHA256 та свіжості `auth_date` на сервері. Можна створити акаунт
  через Telegram або прив'язати Telegram до акаунта з підтвердженим email.
- Власні сесії покупців з випадковими токенами, хешами токенів у D1,
  `HttpOnly; Secure; SameSite=Lax` cookies і виходом, що анулює сесію.
- Адаптивне вікно входу, реєстрації та кабінету. Checkout вимагає
  активного акаунта; нові замовлення відображаються лише їх власнику.
- Нові таблиці у `migrations/0001_customer_auth.sql`: `customers`,
  `customer_sessions`, `customer_email_verifications`, `customer_orders`.
  **Наявні таблиці, облікові записи, замовлення та Telegram-зв'язки
  ця міграція не змінює.** Старі гостьові замовлення не приписуються
  автоматично новим акаунтам — це вимагало б додаткової перевірки власності.

### Перед використанням на production

1. Погодити схему, зробити резервну копію production D1, потім перевірити
   міграцію в окремій **локальній** D1. Реальна міграція та deploy не
   виконувалися.
2. Підключити [Cloudflare Email Sending](https://developers.cloudflare.com/email-service/)
   для `tanukishop.pp.ua`, підтвердити домен відправника, перевірити
   доступність сервісу для поточного тарифу. У Wrangler підготовлено binding
   `EMAIL` та не секретну адресу `noreply@tanukishop.pp.ua`.
   Без справного email-сервісу реєстрація через email завершується помилкою,
   а не створює помилково підтверджений акаунт.
3. У [BotFather](https://t.me/BotFather) виконати `/setdomain` для
   `tanukishop.pp.ua` у бота `TanukiShopNotifyBot`. Поточний секрет
   `TELEGRAM_BOT_TOKEN` лишається в Cloudflare Secrets, не в GitHub.
4. Після локальних та інтеграційних тестів **окремо погодити** застосування
   міграції та публікацію нового Worker. До того стара версія сайту працює
   без змін.

### Ще попереду

Окремі сторінки товарів, відновлення забутого пароля, зміна email,
захист від повторного створення замовлення (ідемпотентність) і майбутня
синхронізація із KeyCRM. Їх не позначено як готові.

Код віджета KeyCRM уже є в `public/index.html`, однак 20.10.2026 його
завантаження в браузері завершилося помилкою `Invalid widget token`.
Потрібний оновлений чинний код віджета з KeyCRM. Приватні API-ключі
не додавайте у frontend або репозиторій.
